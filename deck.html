Why data-driven security

Detection is a data problem first, a model problem second

Real access, no malware

About 82% of detections in 2025 had no malware. Attackers used real passwords and trusted paths. So the clue is unusual behaviour in context, not a bad file.

Attacks before the fix

Mandiant estimates that attackers now use a weakness about 7 days before the fix exists. So we must predict which weaknesses to fix first.

Three things data gives defenders

  • Visibility: you cannot detect what you do not record
  • Context: who, what, how important, how exposed
  • Feedback: results that teach the system after each incident

From raw events to decisions

Telemetry records from computers, logins, network, cloud
Data engineering clean, add context, check quality
Baselines what is normal for this user or device
Detection rules, machine learning, threat intelligence
Decision a person, a person with help, or automatic
Feedback decisions become labels for learning

Case 1 · AI-driven defence wins

Big Sleep: an AI agent finds a bug before attackers do

What happened

  • Oct 2024: Google Project Zero and DeepMind's Big Sleep agent found a serious memory bug in SQLite (a stack buffer underflow)
  • It was reported and fixed on the same day, in a development version, before the official release
  • 2025: Google said Big Sleep helped stop the use of CVE-2025-6965 just before attackers could exploit it

Where people stayed involved

  • Researchers started the search from an old, fixed bug (variant analysis)
  • People checked the result, reported the bug and owned the fix process

Why defence won

  • Speed and scale: AI read code faster than any analyst
  • Early action: found before release
  • Ready process: maintainers could fix it quickly
Warning

The bug was in a development version, and the claims come from the vendor. The lesson is the pattern, not the hype.

Adversarial resilience

Resilience has many layers. It is not one feature of the model

Data layer
Check the origin and integrity of training data and feedback labels. Set data quality targets. Keep unverified sources separate.
Model layer
Robust training, calibration, tests of old versus new models, and monitoring of drift and performance on hidden and adversarial test sets.
System layer
Levels of autonomy, a kill switch and rollback, minimum rights for agents, rate limits, and different detectors (rules + ML + intelligence).
Human layer
Power to override, structured review of unclear cases, reporting without blame, purple-team and incident exercises.
Governance
Inventory of models, audit trails, resilience metrics, and red-team tests of AI parts before and after launch.
Test question: if an attacker controlled 5% of your training data, or hid instructions in an email your AI assistant reads, what would break first? Who would notice?

Read an alert: score, threshold and two kinds of mistake

Score and threshold

A model gives each event a score from 0 to 1. A higher score means more unusual. A score is a clue, not proof. The threshold is the line where you raise an alert.

Two kinds of mistake

  • False alarm (false positive): an alert, but no attack. It wastes time and trust.
  • Missed attack (false negative): an attack, but no alert. It costs money and data.
In the simulation, a score like 0.91 is a strong clue, but you still ask for context. If data is missing, the score can be too low.

Before you act: get context, then choose how wide to contain

Six context questions

  1. Who? The user, their role and their normal work
  2. What? The system, and how important it is
  3. Where? Is the place or network normal?
  4. When? Is the time normal?
  5. Compare: What do similar users or devices do?
  6. What else? Other computers, accounts or tokens with the same clue
What's yours?: identity records, asset lists and past logs.

Key words · 1 of 2

Data and detection, in simple English

  • Telemetry: records that systems send about what they do
  • Log: a written record of events on a system
  • Baseline: what is normal for a user or device
  • Anomaly: something unusual
  • Score: a number from 0 to 1. Higher means more unusual
  • Threshold: the score line where an alert is raised
  • Context: extra facts about who, what, where and when (also called enrichment)
  • True positive: a real attack that raised an alert
  • False positive: an alert when there is no attack (a false alarm)
  • False negative: an attack that raised no alert (a miss)
  • Label: a saved verdict, real or false alarm, so the model can learn
  • Drift: a model slowly becomes less accurate as data changes
  • Dwell time: how long an attacker stays hidden
  • Breakout time: time from first access to spreading to another system

Key words · 2 of 2

Attacks and decisions, in simple English

  • Phishing: a fake message that tricks you
  • Deepfake: fake video or voice made by AI
  • Beacon: a small signal sent again and again to an attacker
  • Password spray: trying a few common passwords on many accounts
  • MFA: a second proof of identity, besides the password
  • MFA fatigue: many approval requests, hoping the user taps "approve"
  • Poisoning: an attacker adds bad data to teach the model wrong things
  • SOC: the team that watches for attacks
  • SOAR: tools that run response steps automatically
  • Containment: stopping the attacker from spreading or acting
  • Safe list (allowlist): things you choose not to alert on. A risky shortcut
  • Check through another channel: confirm a request by a different route, such as a phone call to a known number
  • Two-person approval: a second person must approve before money moves
  • Human in the loop: a person checks or approves the AI's work
